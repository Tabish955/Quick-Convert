Hey, Phase 1 is wrapped up and pushed to main.

Whenever you're ready, pull the repo and create your branch:
git checkout main
git pull origin main
git checkout -b phase-2-ui

Your main focus for Phase 2 is giving the app a proper visual overhaul using Wpf.Ui controls (Windows 11 Fluent design, rounded cards, acrylic/mica background, and clean light/dark themes). All the MVVM plumbing, dependency injection, and data bindings are already wired up, so you won't need to write any backend or conversion logic.

The two files you need to redesign are located in `src/QuickConvert.UI/Views`:

1. `QuickPopupWindow.xaml`:
This is the lightweight popup that opens right near the cursor when files are sent from Explorer. It's connected to `QuickPopupViewModel`. Here are the properties and commands already waiting for you:
- Header info: `FileSummary`, `FileCount`, `DetectedCategory`
- Target format dropdown: `AvailableTargetFormats` (ObservableCollection) and `SelectedTargetFormat`
- Progress & status: `OverallProgress` (0 to 100), `StatusMessage`, `IsConverting`, `ConversionCompleted`
- Button commands: `ConvertNowCommand`, `CancelConversionCommand`, `OpenFullDashboardCommand`, `OpenOutputFolderCommand`

2. `MainDashboardWindow.xaml`:
This is the full batch converter dashboard, wired to `MainDashboardViewModel`:
- Queue view: bind your DataGrid or cards to `Jobs` (each job exposes `FileName`, `FormattedFileSize`, `Category`, `TargetExtension`, `ProgressPercentage`, and `StatusText`).
- Top bar: `AddFilesCommand`, `SelectedGlobalFormat` and `AvailableGlobalFormats`, `OutputFolderPath`, `BrowseOutputFolderCommand`, `OpenOutputFolderCommand`.
- Queue actions: `StartQueueCommand`, `CancelAllCommand`, `ClearCompletedCommand`.

The mock engine (`MockConversionEngine`) is already working. If you hit F5 in Visual Studio or run `dotnet run --project src/QuickConvert.UI`, drop in a couple of files and hit Convert, you'll see a realistic 2.5-second live progress bar and dummy output files created. You can use that to test your animations, progress bars, and states right away.

Just two quick things to keep in mind:
- Don't touch anything in `QuickConvert.Core` — that layer is frozen for Phase 1.
- Avoid writing business or conversion logic in `.xaml.cs` code-behind; keep everything bound to the ViewModel commands.

I also added a detailed reference in `PHASE_2_SPEC.md` at the project root if you need exact property signatures. Ping me if you run into any issues getting it running.
